# UM3 component tests

Run from the Marlin repository root:

```sh
python3 buildroot/tests/um3/run.py
python3 buildroot/tests/um3/run_thermal.py
python3 buildroot/tests/um3/run_interlock.py
python3 buildroot/tests/um3/run_motion.py
python3 buildroot/tests/um3/run_power.py
```

These compile the actual platform-independent production implementations as C++11
with AddressSanitizer and UndefinedBehaviorSanitizer. A C++ compiler and Python 3
are required; there are no additional dependencies. Set `CXX` to select a compiler.
Temporary build files are removed automatically.

The thermal, interlock and power suites consume `stock_oracle.json`, generated by
executing selected shipped ARM instructions under Unicorn. Native tests need no
emulator or vendor binary. The optional producer, pinned dependencies, precise
coverage and architecture limits are documented in the
[recovery report](../../../docs/ultimaker3/recovery.md).

The committed packet and CRC fixtures were produced with the unmodified Python
modules in the official UM3 `5.3.0.20211003` image. To independently check them
against an extracted image:

```sh
python3 buildroot/tests/um3/run.py --stock-root /path/to/rootfs/usr/share/griffin
```

The runner verifies the four recorded source digests before importing only the
CRC, packet, and response-parser modules. It does not start Griffin or communicate
with a printer. `fixtures.json` records the source digests and wire bytes.

Coverage includes fragmented and corrupt packets, maximum-length payloads,
reserved/illegal bytes, CRC bytes equal to the framing byte, resend after queue
backpressure, duplicate rejection, sequence wraparound, and exact response bytes.
Responses use the CRLF framing emitted by public UM3 `MarlinSerial::println()`;
the shipped host parses the stripped line.

Later binary recovery found that the shipped ARM simulator's `println()` emits
LF alone. The historical reconstruction branch restores that behavior. These
isolated formatter fixtures retain public-source CRLF, which the host also
strips. The integrated production formatter below uses and verifies shipped LF
framing against the stock host parser.

The isolated decoder test does not exercise the production command queue or
hardware. Passing only these
tests does not establish firmware, thermal, motion, or machine compatibility.

## Integrated frontend and mocked hardware

`python run_integration.py` compiles the actual UM3 frontend/protocol, thermal/PID,
probe and core-EEPROM code with ASan/UBSan and test-only hardware/backend mocks.
It exercises production boards 2/3 and refuses newer boards. No test HAL is used
by PlatformIO. Add `--stock-root /path/to/usr/share/griffin` to independently
validate every captured response with the SHA-pinned stock host parser.
See [the integration ledger](../../../docs/ultimaker3/integration.md) for covered
scenarios and the distinction between mocked boundaries and AVR/hardware tests.
